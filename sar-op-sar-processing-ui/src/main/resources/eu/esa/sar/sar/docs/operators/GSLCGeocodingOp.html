GSLC Terrain Correction

GSLC Terrain Correction

Description

The GSLC Terrain Correction operator performs Geocoded Single Look Complex (GSLC) generation by transforming SAR data from slant-range geometry to a map projection while preserving phase information. This process is essential for applications that require analysis of the complex SAR signal in a geographic coordinate system, such as interferometry (InSAR) and polarimetry (PolSAR).

Technical Background

Traditional SAR geocoding methods focus on correcting geometric distortions in the magnitude of the SAR image, often discarding the phase. However, the phase component of the complex SAR signal contains valuable information about the sensor-to-target distance. Preserving this phase during geocoding is crucial for advanced applications.

The GSLC generation process involves the following key steps:

  1. Precise Geometry Calculation: Using precise orbit state vectors and a Digital Elevation Model (DEM), the operator accurately determines the geographic coordinates (latitude, longitude, height) for each pixel in the output grid.
  2. Zero Doppler Search: For each point on the ground, the operator finds the corresponding azimuth time (zero Doppler time) in the source SAR image.
  3. Slant Range Calculation: The precise distance (slant range) from the sensor to the ground point is calculated. Optional corrections for Solid Earth Tide and tropospheric path delay may be applied at this step. They change the flatteningPhase band (and the flattened output); the tide also moves the sampling position by a sub-pixel amount. In the default (unflattened) mode Interferogram recomputes its own reference phase without them, so they are not a correction of the interferogram. In a stack of flattened products they are part of the phase removed from each product, so the modelled tide and dry-delay differences are removed from the interferogram.
  4. Complex resampling in baseband: I/Q are interpolated at the source position with a high-fidelity kernel (default BISINC_5_POINT). In range a focused SLC is already in baseband. In azimuth the Doppler-centroid carrier (TOPS: deramp/demod) is removed before the kernel. For stripmap it is put back after the kernel; for TOPS the output stays deramped unless Restore TOPS azimuth carrier is on.
  5. Optional flattening (off by default): with Output phase-flattened complex data on, each pixel is multiplied by exp(+j·4πRmod/λ) after the kernel, where Rmod is the orbit+DEM range model. By default no flattening is applied and the output keeps the natural SLC phase −4πR/λ + ψscat. This unflattened output is the default for InSAR — the Reference · conj(Secondary) product then carries the differential-range phase exp(−j · 4π(Rref − Rsec)/λ).

This process results in a Single Look Complex (SLC) image that is precisely geocoded to a map projection, with its phase correctly representing the sensor-to-target path length for each pixel in the new grid.

Output metadata stamps

The operator writes two custom attributes into the target product's abstracted metadata so downstream operators (notably CreateStack) can rebuild the same processing context when given only the GSLC on disk:

Attribute Type Purpose
gslc_source_slc_path string (file path) Absolute path of the slant-range SLC this GSLC was geocoded from. CreateStack reads this stamp when it estimates the coregistration bias of a Secondary it geocodes itself (Back-Geocoding + ESD for TOPS, a cross-correlation offset field for stripmap). If the stamp is missing (e.g. the Reference is a subset of a GSLC and the subset operation stripped it), CreateStack falls back to a name-based search for the source SLC in the Reference's directory.
gslc_output_flattened string ("true" / "false") Whether the GSLC was built with Output phase-flattened complex data = true. Used by CreateStack to ensure an auto-built Secondary GSLC matches the Reference's flattening state, and by Interferogram, which skips its own flat-Earth/topographic phase subtraction when every product in the stack is flattened and refuses a stack that mixes the two states.

Processing Workflows

Single GSLC Generation

Stripmap SLC

  Stripmap SLC product (validated on ERS-1/ERS-2)
    → Apply-Orbit-File
    → GSLC-Terrain-Correction

Do not add Thermal-Noise-Removal here. It converts complex data to detected intensity and destroys the phase that GSLC needs.

TOPS (IW/EW) SLC

  S-1 IW SLC Product
    → Apply-Orbit-File
    → TOPSAR-Split (select one subswath, e.g. IW2, and polarisation)
    → GSLC-Terrain-Correction

Repeat for each subswath if full-swath coverage is needed. The operator handles burst deramping, geocoding, and burst mosaicking internally.

GSLC-Based InSAR

The GSLC approach replaces the explicit BackGeocoding / ESD / Deburst / Merge / TerrainCorrection chain with a single geocoding step per acquisition. Each scene becomes a phase-preserving complex product on a common map grid, and the rest of the InSAR chain consumes those directly.

Simplest path — only the Reference is geocoded explicitly

  Reference SLC (Date 1)         Secondary SLC (Date 2)
    → Apply-Orbit-File          → Apply-Orbit-File
    → GSLC-Terrain-Correction   (raw SLC, no GSLC step)
      ↓ Reference GSLC                    ↓
            CreateStack(Reference GSLC + raw Secondary SLC)
                       ↓
            (CreateStack auto-geocodes the Secondary on the Reference grid
             with the Reference's DEM, tide and troposphere settings,
             reloads the Reference's source SLC from the gslc_source_slc_path
             stamp, measures the residual offset (TOPS: Back-Geocoding + ESD,
             constant (Δr, Δa); stripmap: cross-correlation offset field),
             re-geocodes the Secondary only if the offset exceeds 0.05 pixel
             anywhere in the scene, and stacks the two.)
                       ↓
            Interferogram → (optional) Goldstein-Phase-Filtering → Phase-Unwrapping

Explicit path — both scenes geocoded up front

  Reference SLC                         Secondary SLC
    → Apply-Orbit-File                  → Apply-Orbit-File
    → GSLC-Terrain-Correction           → GSLC-Terrain-Correction
      ↓ Reference GSLC                      ↓ Secondary GSLC
                CreateStack
                     ↓
            Interferogram → ...

In this path Create Stack stacks a Secondary GSLC that is already on the Reference lattice, with the same flattening and carrier settings, as-is: no re-geocoding and no bias estimation. A residual offset is estimated only for Secondaries that Create Stack geocodes itself (the simplest path above). On well-synchronised Sentinel-1 pairs that bias is below about 0.04 pixel, under the 0.05-pixel level below which Create Stack ignores it, so no manual offset is needed.

Advantages of the GSLC approach:

  • Fewer processing steps (no deburst, merge, or separate terrain correction)
  • Each acquisition can be processed independently and in parallel
  • The output is directly geocoded — ready for time-series analysis
  • Consistent geocoding across all acquisitions (same DEM and geometry)
  • Secondary coregistration is folded into CreateStack — user runs GSLC once on the Reference, feeds raw SLC secondaries, and CreateStack handles the rest.

Multi-Subswath Coverage

For full IW coverage (IW1 + IW2 + IW3), process each subswath independently:

  For each subswath (IW1, IW2, IW3):
    TOPSAR-Split → GSLC-Terrain-Correction

  Then mosaic the 3 GSLC subswaths per date.

Alternatively, process each subswath interferogram independently, then mosaic the interferograms.

Technical Notes

TOPS Azimuth Deramping

In TOPS (IW/EW) mode, the antenna steers during each burst, imparting a quadratic phase ramp in azimuth. This ramp must be removed (deramped) before any interpolation to prevent aliasing. The operator handles this internally for TOPS products:

  1. For each burst, the azimuth deramp and demodulation phase is computed using the Doppler rate and centroid annotations from the product metadata.
  2. The phase is applied to the source complex data before resampling.
  3. By default the output stays deramped (carrier-free, as OPERA CSLC). The deramp phase is written to azimuthCarrierPhase so that Interferogram can subtract the carrier difference. Restore TOPS azimuth carrier re-ramps it; do not use that for InSAR.
  4. Range flattening is applied only when Output phase-flattened complex data is on, as for stripmap.

Stripmap Azimuth Deramp (residual Doppler centroid)

For Stripmap products with a non-zero residual Doppler centroid (e.g. ENVISAT ASAR IMS), the operator applies a sample-by-sample azimuth deramp / reramp using the Doppler_Centroid_Coefficients metadata field. This prevents phase aliasing during complex interpolation and is essential for coherent GSLC stacking.

Phase Flattening

φ = 4πRmod/λ

It is never applied before resampling, because the per-column ramp would alias. By default it is not applied at all and is only written to the flatteningPhase band; ref · conj(sec) of the default output then gives exp(−j · 4π(Rref − Rsec)/λ). With the option on, it is applied after the kernel. The flattened output keeps the residuals, and Interferogram, seeing that every product in the stack is flattened, does not subtract the flat-Earth phase again. Use one mode across a stack: Interferogram refuses a mixed stack, and Create Stack puts the Secondaries it geocodes onto the Reference's mode.

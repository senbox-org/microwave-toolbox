SAR Workflows: InSAR Time Series

InSAR Time Series

From a stack of Sentinel-1 IW SLCs of one track you get displacement per date and mean velocity. You can do this inside SNAP (optional Phase Linking, a network of interferograms, SNAPHU, SBAS Inversion), or prepare the data for StaMPS or PyRate. All routes start from the same coregistered, debursted stack.

Before you start

  • Data: many IW SLCs of one relative orbit covering the same bursts. The code accepts 3 epochs, but robust velocities need many more dates over a period much longer than the seasonal signals.
  • Network: open Radar > Interferometric > InSAR Stack Overview to see the baselines and pick a central Reference date.
  • Orbits, DEM, SNAPHU: as for a single pair (see the Sentinel-1 DInSAR workflow).
  • Ready-made graphs: Radar > Coregistration > S1 TOPS Coregistration has S-1 TOPS Split Apply Orbit and S-1 TOPS Joint Coregistration (write shifts to file) (Back-Geocoding and ESD on a product set). Radar > Interferometric > PSI\SBAS > StaMPS Export is also a graph.

Steps: the coregistered stack

  1. S-1 TOPS Split and Apply Orbit File on every date, with the same sub-swath and bursts.
  2. S-1 Back Geocoding (Back-Geocoding; help) with all dates at once; the first product is the Reference.
  3. S-1 Enhanced Spectral Diversity (Enhanced-Spectral-Diversity; help). For a stack it estimates shifts over a network: Temporal baseline type Number of images, Maximum temporal baseline 4 and Integration method L1 and L2 by default.
  4. S-1 TOPS Deburst (TOPSAR-Deburst; help). Phase Linking and StaMPS Export both refuse burst products. For StaMPS, form the interferograms first (see below).

Steps: in-SNAP route

  1. Phase Linking, optional (PhaseLinking, Radar > Interferometric > Phase Linking; help). Worth it over distributed scatterers (fields, rangeland). Defaults: SHP window 21 (azimuth) × 7 (range), SHP Test KS, Minimum SHPs 20, Phase Estimator EVD, Temporal Coherence Threshold 0.6, Reference epoch = median date. It writes i_pl_* / q_pl_* bands and tempCoh_<pol>. It estimates the whole stack at once, so stacks of more than about 50 dates are slow.
  2. Multi-Reference InSAR (MultiMasterInSAR, Radar > Interferometric > Products; help). List the InSAR pairs as ddMMMyyyy-ddMMMyyyy (either date may come first). The coherence window is 10 × 10 by default. Add elevation band is on by default (DEM Copernicus 30m Global DEM); the band is needed to remove the topographic phase.
  3. Goldstein Phase Filtering (optional), then Snaphu Export, then Batch Snaphu Unwrap (BatchSnaphuUnwrapOp, Radar > Interferometric > Unwrapping; help). Give it the same interferogram product and, as Snaphu Export folder, the sub-folder that Snaphu Export created inside its target folder (named after the product). It runs SNAPHU on every pair and replaces each wrapped phase band with an UnwPhase_ifg_<tag> band (unit abs_phase); the coh_<tag> bands are passed through. It uses an existing snaphu executable in the Snaphu Install Location. On Linux install SNAPHU yourself (or chmod +x the downloaded snaphu binary) and point the tool at its folder, because the automatic download does not set the executable bit; on macOS SNAPHU must always be installed by you. This is the product SBAS Inversion reads. (This direct route follows from the code but has not yet been run end to end; a glance at the statistics of the UnwPhase_ifg bands costs little.)
  4. Snaphu Import (SnaphuImport, Radar > Interferometric > Unwrapping; help), only if you ran SNAPHU outside SNAP instead of Batch Snaphu Unwrap (the command line is in the header of each <date>_<date>snaphu.conf). Import the results (UnwPhase_ifg_<tag>.snaphu.hdr) one at a time, each time with the previous import (at first the interferogram product) as the first input. Leave Do NOT save Wrapped interferogram unticked, or the coherence bands and earlier pairs are lost. For a stack with more than one Secondary, Snaphu Import keeps the UnwPhase_ifg_<tag> names, sets the unit abs_phase and copies the coh_<tag> bands from the first input.
  5. SBAS Inversion (SBASInversion, Radar > Interferometric > PSI\SBAS; help). Defaults: Reference Epoch Date empty (median date), Coherence Threshold 0.3, Coherence Looks 100. Tikhonov regularisation (weight 0.001) switches on when the condition number exceeds 106. Output Velocity and Output Closure Phase RMS are on. Outputs: displacement_<date> (mm), velocity and velocity_uncertainty (mm/year), temporal_coherence, closure_phase_rms (no-data where no closed triplet of usable pairs exists, for example in a sequential network).
  6. Range-Doppler Terrain Correction of the results.

Export routes

  • StaMPS (PS): on the burst stack run Interferogram, then TOPSAR-Deburst, then Topographic Phase Removal with Output elevation band and Output lat/lon band ticked. Feed the debursted SLC stack (first) and this interferogram product (second) to StaMPS Export and choose a target folder. Only the PSI format is implemented.
  • PyRate (SBAS): run Multi-Reference InSAR, optional Goldstein filtering, and Snaphu Export. Then Export to PyRate (Radar > Interferometric > PSI\SBAS > Export to Pyrate) runs a graph of Batch Snaphu Unwrap, Terrain Correction and the PyRate writer (File > Export > SAR Formats > PyRate export). It writes GeoTIFFs with GAMMA-style headers and input_parameters.conf; run pyrate workflow -f input_parameters.conf.

Check the result

  • temporal_coherence close to 1 and a small closure_phase_rms mark pixels whose network is consistent. A high closure RMS shows sub-cycle inconsistency (for example soil moisture or vegetation change). Each closure is wrapped to (−π, π], so whole-cycle unwrapping errors do not show in it; check them with a stable reference area or redundant pairs.
  • A stable area (bedrock, a GNSS station) should show velocity near zero after you subtract the reference.
  • Phase Linking: inspect tempCoh. Pixels below the threshold keep their original phase.

Common pitfalls

  • Treating SBAS results as absolute. Displacement is relative to the reference epoch (velocity is not), and both carry an arbitrary spatial constant because no reference point is subtracted; subtract a stable area.
  • A disconnected network. The regularised solution is then a smoothed guess across the gap.
  • Using Phase Linking for isolated point targets. It averages over similar pixels; use StaMPS for PS.
  • Only short pairs over vegetation. Check closure_phase_rms; add longer pairs or use Phase Linking.

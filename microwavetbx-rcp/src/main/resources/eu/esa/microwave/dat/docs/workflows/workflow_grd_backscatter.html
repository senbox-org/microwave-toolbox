SAR Workflows: Sentinel-1 GRD to Terrain-Flattened Backscatter

Sentinel-1 GRD to Terrain-Flattened Backscatter

This chain turns a Sentinel-1 GRD product into terrain-flattened γ0 (γ0T) on a map grid. The backscatter is normalised by the true illuminated area, so values can be compared across dates, orbits and slopes. This is what is usually called analysis-ready backscatter. Input: one Sentinel-1 IW or EW GRD product.

Before you start

  • Data: a Sentinel-1 GRD product (.SAFE folder or zip). For a time series, process every date with the same chain and the same DEM.
  • Orbits: precise orbit files are downloaded automatically. They exist about 20 days after acquisition; for newer data use restituted orbits.
  • DEM: Terrain Flattening and Terrain Correction both download the Copernicus 30 m DEM by default. Use the same DEM in both steps.
  • Graphs: SNAP ships no ready-made graph for the full chain. Build it once in the Graph Builder, save it, and run it on many products with Batch Processing. The Graph Builder menu Graphs > Radar > Standard Graphs holds partial graphs (Calibrate, Orthorectify).

Steps

  1. Apply Orbit File (Apply-Orbit-File, Radar menu; help). Orbit State Vectors defaults to Sentinel Precise (Auto Download). Switch to Sentinel Restituted for data younger than about three weeks. Do not fail if new orbit file is not found is off by default, so the run stops rather than silently keeping the annotated orbit.
  2. S-1 Remove GRD Border Noise (Remove-GRD-Border-Noise, Radar > Sentinel-1 TOPS; help). Apply it first: it refuses calibrated input, and after Thermal Noise Removal dark surfaces at the image edge are more easily mistaken for border noise (the Bidirectional method logs a warning). Border detection method defaults to Auto. Products from IPF 2.90 onwards are already masked by the processor and pass through unchanged, unless you tick Also process products from IPF 2.90 and later (off by default).
  3. S-1 Thermal Noise Removal (ThermalNoiseRemoval, Radar > Radiometric; help). Remove Thermal Noise is on by default. Clip Negative Values is also on (floor 10−5). Turn it off if you will average the result later (composites, large-window statistics), because clipping biases averages upward. The operator refuses multilooked or resampled input and products from IPF versions older than 2.50.
  4. Calibrate (Calibration, Radar > Radiometric; help). Tick Output beta0 band; by default only Output sigma0 band is on. Leave Scale in dB off (the default). If you skip this step, Terrain Flattening calibrates uncalibrated input to β0 itself.
  5. Radiometric Terrain Flattening (Terrain-Flattening, Radar > Radiometric; help). It reads the Beta0_<pol> bands and writes γ0T as Gamma0_<pol>, still in radar geometry. Digital Elevation Model defaults to Copernicus 30m Global DEM. Output Terrain Flattened Sigma0 is off by default. With an external DEM in geoid heights, tick External DEM Apply EGM: here it is off by default, unlike in Terrain Correction.
  6. Speckle filtering, optional (Speckle-Filter, Radar > Speckle Filtering > Single Product Speckle Filter; help). The default filter is Lee Sigma. For a stack of dates the Multi-temporal Speckle Filter keeps more spatial detail. Skip this step if you will average over fields or polygons anyway.
  7. Range-Doppler Terrain Correction (Terrain-Correction, Radar > Geometric > Terrain Correction; help). Use the same DEM as in step 5 (default Copernicus 30m Global DEM). Pixel Spacing (m) 0, the default, takes the finer of the ground-range and azimuth spacing: 10 m for IW GRDH. Map Projection defaults to WGS84(DD); choose a UTM zone if you need metric pixels. Leave Apply radiometric normalization off and tick Save layover shadow mask for quality control.
  8. Convert to dB for display only (LinearToFromdB, Raster > Data Conversion). Keep the linear bands for any averaging or statistics.

Check the result

  • Slopes: in mountains, slopes facing the radar and slopes facing away should have similar brightness over the same land cover. Bright foreslopes mean that flattening was not applied, or that you are looking at the Gamma0 band from Calibrate instead of the one from Terrain Flattening.
  • Layover and shadow: overlay layoverShadowMask. Values inside layover (1), shadow (2) or both (3) are not reliable.
  • Edges and seams: there should be no bright or dark strips along the near- and far-range borders, and no noise bands at the sub-swath seams of the cross-polarised channel.
  • Geolocation: coastlines and roads should line up with a reference map. A systematic shift points to a missing orbit update or an external DEM in the wrong height datum.

Common pitfalls

  • Calibrating to Sigma0 only: Terrain Flattening then stops with "TerrainFlattening requires beta0 or T3, C3, C2 as input".
  • Ticking Scale in dB before Terrain Flattening. It does not check the unit and treats Beta0_VV_dB as linear.
  • Ticking Apply radiometric normalization in Terrain Correction on Terrain Flattening output. The incidence correction is then applied twice.
  • Comparing a Gamma0 band from Calibrate (ellipsoid γ0) with one from Terrain Flattening. They have the same name but are different quantities; check the processing graph in the metadata.
  • Averaging or compositing in dB. The mean of dB values is biased low.

Import UAVSAR

UAVSAR is NASA/JPL's airborne L-band polarimetric SAR. Its main design goal is repeat-pass interferometry. SNAP reads UAVSAR PolSAR products with the UAVSAR reader.

Mission

  • Operator: NASA/JPL. The radar is carried in a pod under a NASA Gulfstream III jet.
  • Radar: L-band, 1217.5–1297.5 MHz (80 MHz bandwidth, wavelength about 24 cm), quad polarisation (HH, HV, VH, VV).
  • Acquisitions: campaign flights rather than a fixed orbit and revisit.

Supported products

ExtensionContent
.slcSingle look complex, one file per polarisation, slant range
.mlcMulti-looked cross products (covariance terms), slant range
.grdThe same cross products projected to a latitude/longitude grid

Height (.hgt), slope and incidence files are not read. The reader also accepts the extension .dat, but see Known limitations.

How to open

Select one data file (.slc, .mlc or .grd). The annotation file (.ann) must be in the same folder; the reader uses the first .ann file it finds there. All files in the folder with the same extension become bands of one product, so keep one product per folder.

What you get

  • SLC: i_HH/q_HH, i_HV/q_HV, i_VH/q_VH, i_VV/q_VV.
  • MLC and GRD: the six cross products, named like covariance-matrix elements: C11 (HHHH), C22 (HVHV), C33 (VVVV) as intensities, and C12 (HHHV), C13 (HHVV), C23 (HVVV) as _real/_imag band pairs. Values are linear power.
  • Geocoding from the four scene corners in the annotation.

The mission and acquisition parameters SNAP uses are listed in the Abstracted Metadata.

Known limitations

  • Products are already calibrated by JPL; SNAP has no UAVSAR calibrator.
  • Corner-based geocoding is approximate, also for .grd files, although these are on a regular latitude/longitude grid.
  • The compressed Stokes-matrix .dat files (10 bytes per pixel) are accepted by extension but not decoded; use the MLC or GRD files instead.
  • Apply Orbit File does not apply to airborne data.

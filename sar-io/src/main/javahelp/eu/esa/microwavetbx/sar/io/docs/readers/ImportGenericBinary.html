Import Generic Binary

The Generic Binary reader opens a raw binary raster whose layout you describe yourself. For complex (i/q) data use Import Complex Generic Binary.

Format

A headerless (or fixed-size header) binary file of real-valued samples, stored line after line, band after band (band sequential, BSQ). No mission is implied.

Supported data

  • Data types: int8, uint8, int16, uint16, int32, uint32, float32, float64.
  • Byte order: big endian or little endian.
  • Interleave: BSQ only.

How to open

  1. Choose File > Import > SAR Formats > Generic Binary and select the file. The file filter suggests .bin, .bil, .bsq, .bip, .img, .ras and .dat, but any file can be selected. The extension does not change how the file is read.
  2. In the second dialog, enter Width, Height, Number Of Bands, Data Type, Header Bytes (bytes to skip at the start of the file) and Byte Order.

This reader is not used by File > Open Product; use the import menu.

What you get

  • Bands named band1, band2, ... with no unit. The product type is Generic.
  • No geocoding and no SAR metadata, unless an XML metadata file is found: a file with the same name and the extension .xml, or metadata.xml in the same folder. Such a file (as written by SNAP) is loaded into the Abstracted Metadata, including any tie-point grids it holds.

Known limitations

  • Only single-band files are read correctly. With Number Of Bands greater than 1, every band currently shows the data of the first band.
  • Multi-band BIL and BIP layouts are not supported, even though the file filter lists their extensions.
  • Without a metadata file, SAR operators that need orbit, timing or geocoding information cannot run.

Recommended next step

Check the image in the viewer, set the band unit in the band properties if you know it, and work with Band Maths. When the data came from a supported mission, open the original product with its mission reader instead.

Product format specification

None: this is a user-described raw format.

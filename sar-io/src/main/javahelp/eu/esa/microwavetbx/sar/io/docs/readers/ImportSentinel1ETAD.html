Import Sentinel-1 ETAD

The Sentinel-1 Extended Timing Annotation Dataset (ETAD) is an auxiliary product that corrects the timing, and so the geolocation, of Sentinel-1 SLC images. SNAP opens ETAD products with the SENTINEL-1 ETAD reader so that you can inspect the correction layers. The image products themselves are described on Import Sentinel-1.

Mission

  • Producer: ESA, with DLR as contractor, for the Copernicus Sentinel-1 mission.
  • Content: correction layers for the atmospheric path delays (troposphere and ionosphere), for solid Earth tides, and for effects of the Sentinel-1 SAR processor.
  • Sampling: regular grids of about 200 m, organised by sub-swath and burst, following the structure of the matching SLC product.
  • Coverage: one ETAD product per Sentinel-1 SLC data take.

Supported products

ProductModesPackaging
ETAD (product type ETA)IW and Stripmap (SM) SLC data takes SAFE folder with one NetCDF file and an XML annotation file, or its ZIP archive

How to open

Use File > Open Product; there is no entry under File > Import. Select one of:

  • the manifest.safe file inside the S1..._ETA_....SAFE folder;
  • the .SAFE folder itself;
  • the ZIP archive (its name starts with S1 and contains _ETA_).

The _ETA_ part of the name is what tells SNAP that the product is ETAD; the normal SENTINEL-1 reader does not open these products.

What you get

  • One band per correction layer and burst, named <sub-swath>_<burst>_<layer>, for example IW1_Burst0001_troposphericCorrectionRg. Layers include the tropospheric, ionospheric and geodetic range corrections, the azimuth corrections (for example bistatic and FM-rate mismatch) and the sums of all range and all azimuth corrections. The corrections are timing corrections in seconds (unit s); the latitude, longitude and height grids of each burst are also bands. The no-data value is −999.
  • The bands have different sizes (one grid per burst), so the product is a multi-size product.
  • The XML annotation and the NetCDF attributes are under Original_Product_Metadata > annotation. Product type and acquisition parameters are in the Abstracted Metadata.
  • The geocoding is approximate: a simple corner geocoding built from the bounding box of the footprint in manifest.safe.

Known limitations

  • The product contains correction grids, not a radar image; most SAR operators do not accept it.
  • Bursts are not merged on reading, and the approximate geocoding is not suitable for overlaying the layers on other data. Use ETAD Deburst to build one continuous layer.

Recommended next step

  • To look at one correction layer as an image: ETAD Deburst.

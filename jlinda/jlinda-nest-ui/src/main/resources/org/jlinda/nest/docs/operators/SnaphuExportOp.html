SNAPHU Data Export 

The main purpose of SNAPHU data export functionality is three-fold:

  1. To export data (bands) in the format compatible for SNAPHU processing,
  2. To build a SNAPHU configuration file (snaphu.conf), the file where processing parameters for SNAPHU are being stored,
  3. To construct a container product that will store metadata and bands to be used when SNAPHU results are being ingested back into the Toolbox.

The input must be a coregistered interferogram product that contains a wrapped phase band and a coherence band; the operator stops with an error if either is missing.

Parameters

The SNAPHU parameters below are written into snaphu.conf; they control the later SNAPHU run, not the export itself.

  • Target folder (targetFolder): folder the exported files and snaphu.conf are written to. Required; it is created if it does not exist.
  • Statistical-cost mode (statCostMode, SNAPHU STATCOSTMODE): TOPO, DEFO, SMOOTH or NOSTATCOSTS; default DEFO. Use TOPO for topographic (DEM) interferograms, DEFO for deformation interferograms, SMOOTH for generic smooth data, and NOSTATCOSTS to run without statistical costs.
  • Initial method (initMethod, SNAPHU INITMETHOD): algorithm for the initial unwrapped solution, MST (minimum spanning tree) or MCF (minimum cost flow); default MST.
  • Number of Tile Rows (numberOfTileRows, SNAPHU NTILEROW) and Number of Tile Columns (numberOfTileCols, SNAPHU NTILECOL): SNAPHU splits the image into this many tiles and unwraps them in parallel; default 10 each. Set both to 1 to unwrap the image as a single tile.
  • Number of Processors (numberOfProcessors, SNAPHU NPROC): number of SNAPHU processes run at the same time; default 4.
  • Row Overlap (rowOverlap, SNAPHU ROWOVRLP) and Column Overlap (colOverlap, SNAPHU COLOVRLP): overlap between neighbouring tiles, in pixels; default 200 each.
  • Tile Cost Threshold (tileCostThreshold, SNAPHU TILECOSTTHRESH): cost threshold for the boundaries of reliable regions when tiles are joined (dimensionless); default 500. A larger value gives smaller regions: safer, but slower.

External processing with SNAPHU

Given that the SNAPHU software is properly installed and configured, unwrapping of exported product is quite straightforward. In the directory where the SNAPHU product is being saved, the following command is to be executed:

snaphu -f snaphu.conf YOUR_PHASE_BAND.img 99999

where YOUR_PHASE_BAND.img stands for the name of the phase band that is to be unwrapped, and 99999 stands for the line length of YOUR_PHASE_BAND: the number of samples per line, i.e. the number of range samples (columns, the image width in pixels), not the number of lines. Note that the command to be externally called for the phase unwrapping is listed in the header of snaphu.conf file that is created with the SNAPHU writer, with the correct line length already filled in.

Again, it is strongly recommended that before doing any processing with SNAPHU user becomes familiar with the software and process control flags.

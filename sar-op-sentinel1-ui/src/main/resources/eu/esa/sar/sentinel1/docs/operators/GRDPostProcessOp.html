GRD Post-Processing

The GRD Post-Processing operator (GRD-Post) is the last step of the Sentinel-1 SLC to GRD graph. It relabels a Sentinel-1 SLC product that has already been detected, debursted and merged so that SNAP treats it as a GRD product. It does not change any pixel values.

What it does

  • Copies every band of the input unchanged. Virtual bands stay virtual.
  • Renames the product: SLC_ in the product name becomes GRDH. The product type becomes GRD.
  • Updates the abstracted metadata in the same way: SLC_ becomes GRDH in PRODUCT, SLC becomes GRD in SPH_DESCRIPTOR, and PRODUCT_TYPE is set to GRD.

The label is always GRDH, whatever pixel spacing the earlier multilooking produced. The operator does not resample, rescale or convert the data type, and it does not apply any of the IPF GRD processing itself. Those steps are done, or not done, by the operators that come before it in the graph.

Input

The operator refuses the input unless all of these hold:

  • It is a SAR product from Sentinel-1.
  • Its abstracted metadata still has product type SLC.
  • It is detected, not complex. Otherwise: "Data should not be complex. Please first apply SLC to GRD processing."
  • Its sub-swaths are merged. A product with bands named after two IW sub-swaths (IW1 and IW2) or two EW sub-swaths (EW1 and EW2) is refused with "Data should not be in separate swaths."

Output

The same image and bands, with the product name, product type and metadata relabelled as above.
